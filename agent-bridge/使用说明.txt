BatMUD AgentBridge 0.4.0

已安装到 BatMUD 客户端的 plugins 目录(本机原生 macOS 客户端:
~/batclient/plugins/agent-bridge.jar)。每次启动客户端时自动加载。
注意:plugins 目录里不要留任何旧构建副本(包括改过名的),客户端会加载
目录里所有 jar,旧类可能抢先于新类加载,导致版本不更新。

插件仅在本机 127.0.0.1:18765 监听,所有接口均要求随机令牌。
令牌自动保存在 ~/batclient/agent-bridge/token.txt;命令行工具自动读取。
不包含 AI 模型,不读保存密码的配置,也不主动将游戏输出上传外网。
每个连接由独立守护线程处理:长轮询或慢命令派发不会阻塞其他请求,
也不会阻塞游戏回调线程。

命令行(在本项目 agent-bridge 目录执行):
  python3 bridge_cli.py status
  python3 bridge_cli.py read --after 0 --limit 500 --wait-ms 5000
  python3 bridge_cli.py send look --wait 3
  python3 bridge_cli.py follow            # 持续打印新输出,Ctrl-C 停止

每次发送前可先保存 status.latest_seq,随后用 read --after 序号读取新增输出。
send 返回 dispatched=true 仅表示已提交到客户端命令解析器,并不表示服务器执行成功。
send --wait 3 会在 3 秒内长轮询新输出,一有新事件立即返回;不保证响应完整。
不要自动重试发送失败或超时的指令。
发送经过客户端命令解析器,因此现有别名、脚本和客户端命令仍会生效。
连不上时命令行会提示检查客户端是否已启动。

命令限速(0.3.0,实测数据见下):
令牌桶容量 3 条(突发 3 条),之后每 3000ms 连续回充 1 条。
超限返回 429 {"error":"rate_limited","dispatched":false,"retry_after_ms":N}
并带 Retry-After 头。被限速的命令【没有】发进游戏,等 retry_after_ms 后
重试是安全的——这与 504(派发超时、结果未知、不要盲目重试)不同。
status 里的 rate_burst / rate_refill_ms 就是当前配置。
2026-10-24 实测(真实客户端):连发 6 条时前 3 条 200、第 4-6 条 429 且
第 4 条 retry_after_ms=2987(按连续回充精确计算,非死板整 3 秒);
突发 3 条后 +1.5s 探测 429(retry_after_ms=1481,数学上等于
(1-1.5/3)*3000);每 3.1s 发 1 条稳态全部 200。

命令审计日志(0.3.0):
每条实际派发的命令按 JSONL 追加写到
~/batclient/agent-bridge/command-log.jsonl
(字段: time_ms、session、command、after_seq)。
被 400/401/415/429 拒绝的命令不会写入——日志只记真正进入游戏的命令,
用于事后完整回放 agent 到底发了什么。文件不自动轮转,想清空直接删除。

事件落盘(0.4.0,默认关闭):
默认事件只在内存(2000 条环形缓冲),客户端重启即清零。
在 agent-bridge 目录(即 ~/batclient/agent-bridge/)创建名为 persist.txt
的空文件并重启客户端,即开启持久化:每条事件按 JSONL 追加写入同目录
events.jsonl(字段 seq、time_ms、text;不含 raw 以省空间),逐行即时
flush,崩溃也不丢;超过 8MB 时启动时轮转为 events.jsonl.1。
status 新增 persisting 字段显示当前开关。删除 persist.txt 并重启即关闭。

client 客户端库、mcp_server MCP 服务),tests/ 下各有对应测试;
MCP 已注册到本仓库 .zcode/config.json(工作区作用域,本会话项目自动连接)。

行为指纹、memory/ 短期+长期记忆+单词本+地图+日记、refresh.py 快照刷新)。
任何 agent 从仓库根 AGENTS.md 进入即可接班;根 AGENTS.md 是入口。

(DeepSeek flash,key 读 DEEPSEEK_API_KEY 或 ~/.deepseek_api_key;

一致,用量统计在 ~/.deepseek_usage.json)、
mapper.py 房间地图记录与寻路(route/rooms/record/stats)、

map_route/map_rooms/diary_write/kb_search/kb_read/kb_list);

HTTP 接口:
  GET  /status
  GET  /events?after=0&limit=500&wait_ms=0
  POST /command   正文为 UTF-8 单行命令,例如 look
请求头:Authorization: Bearer <token.txt 内容>
命令行工具不使用系统的 HTTP_PROXY / HTTPS_PROXY,始终直连本机。
不允许带 Origin 的浏览器请求;不要将该接口端口映射到公网。
POST /command 若带 Content-Type,只允许 text/* 或
application/x-www-form-urlencoded(curl -d 与 urllib 的默认值),否则 415;
这样能拦住 agent 误把 JSON 体当命令发进游戏。
已知路径用错方法返回 405;未知路径返回 404;非法查询参数返回 400 而非静默忽略;
命令超限返回 429(见上方限速说明)。

/events 参数:
  after    上次读到的 seq,只返回其后的新事件(旧事件在前)。
  limit    本批最多返回多少条(1..2000,默认 500)。
  wait_ms  无新事件时最多阻塞多少毫秒(0..10000,默认 0)。
输出字段:session、latest_seq、oldest_seq、truncated、more、events。
more=true 表示还有未返回的事件,应立即用本批最后一条的 seq 作为 after 续读。
每条事件含 seq、time_ms、text(纯文本)、raw(可能含 ANSI 控制符与客户端协议片段)。
内存保留最近 2000 条事件;客户端重启后 session 改变、序号从头开始。
truncated=true 表示请求的部分旧事件已被缓冲区淘汰,需要重新同步。
status 另含 oldest_seq,可用来判断游标是否仍然有效。
connected 表示网络连接状态,不等同于角色已经登录。

源码:src/local/batbridge/AgentBridge.java
构建:./build.sh(优先用 downloads/bat_interfaces.jar,缺失时自动编译
      build-stubs 下的接口存根;JDK 依次取 BAT_JDK、runtime/ 目录、系统默认,
      产物为 Java 8 字节码,输出 agent-bridge.jar)
测试:先 ./build.sh,再 python3 tests/test_bridge.py。
      harness 在 18766 端口运行(经 -Dbatbridge.port 指定),
      因此游戏客户端开着也能跑测试;正式客户端仍固定用 18765。
      限速参数也可用 -Dbatbridge.rate.burst / -Dbatbridge.rate.refill_ms
      覆盖(仅测试用,客户端默认 3 / 3000)。
      测试会按需自动编译 tests/BridgeHarness.java。

卸载:退出客户端,移走 ~/batclient/plugins/agent-bridge.jar,再启动客户端。
如需轮换令牌:退出客户端,移走 ~/batclient/agent-bridge/token.txt,再启动客户端。
回滚:上一个线上版本已备份为 agent-bridge.installed-backup.jar(当前为
0.2.0),复制回插件目录并重启客户端即可;更早版本在 git 历史里。
